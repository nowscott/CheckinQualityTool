# 阶段性报告：累计聊天检查流程

用户在新任务中发送“阶段性报告”或提交新的聊天质检 Excel 时，按这个流程处理。

1. 归档新聊天文件。
   - 使用 `/Users/nowscott/Documents/聊天记录处理/archive_chat_records.py`。
   - 每份原始 Excel 都存入 `聊天记录处理/archive/原始文件/YYYYMMDD/`。
   - 永不覆盖、永不删除原始版本。
2. 更新累计聊天表。
   - 固定使用 `聊天记录处理/archive/聊天质检明细_累计去重.xlsx`。
   - 它保留聊天质检 Excel 的原工作表、表头、列顺序与格式。
   - 新文件中跨历史未出现的聊天行才会追加；历史原始版本仍完整保留。
3. 跑阶段性报告发送检查。
   - 直接上传钉钉导出的阶段性报告表单分母和累计聊天表到 `/stage-report`，或调用 Worker 的 `stageReport` 模式。
   - 多 Sheet 文件按主列识别分母：优先选择同时包含教师、学号、学员姓名、教研组，并带有“是否发送阶段性报告/是否需要发送”等阶段性报告字段的明细表；窗口期发送明细和教师/教研组汇总表不作为分母。
   - 聊天文件已由“阶段性报告”关键词检索导出，不再重复验证正文关键词。分母有邮箱时按邮箱精确匹配；无邮箱时，教师姓名和聊天发送人姓名均去空格、去末尾数字和“老师”后缀后兜底匹配。
   - 学员按打卡口径优先匹配清洗后姓名后两字（不足两字自动匹配末字）；群名或聊天正文均可作为学员证据；原申诉列不覆盖。
4. 交付前核验。
   - 输出 Sheet、列顺序、师训组长、助理主管、教研组、申诉和“是否需要发送”字段与钉钉表单一致。
   - 只回填“是否发送阶段性报告”为“是/否”。
   - 说明姓名匹配歧义和字段缺失。
