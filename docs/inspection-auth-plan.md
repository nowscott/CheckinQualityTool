# 课堂反馈抽检登录与权限

课堂反馈抽检统一使用自有账号密码登录，生产和 Preview 均不提供兼容密码入口。

## 角色

- `admin`：管理用户、启停账号、分配角色和查看操作审计。
- `operator`：生成抽检名单、替换当前批次、查看和检索历史。
- `viewer`：只读查看教师统计、批次历史和课程明细。

## 账户与会话

- 用户表保存登录名、密码哈希、角色、启用状态、创建时间和最后登录时间。
- 密码使用 Node `crypto.scrypt` 加随机盐哈希，不保存明文。
- 密码允许非空短密码，但生产环境仍建议使用随机长密码。
- 登录后签发 HttpOnly、Secure、SameSite 会话 Cookie，并设置有效期和失效机制。
- 同步签发仅用于恢复界面的非敏感身份提示 Cookie；服务端接口始终以数据库会话和角色为准。
- 停用用户后，后续请求立即失效；密码重置需要管理员操作。
- 同一用户名 15 分钟内连续失败 5 次后暂时锁定。
- 不开放公开注册；账号统一由管理员在“用户管理”区域创建，创建时直接分配 `viewer` 或 `operator` 角色。
- 管理员提升不提供公开 API；管理员可在“用户管理”中调整角色，并撤销旧会话、写入审计。

## 权限边界

- 查看数据、检索教师和查看课程明细：`viewer` 及以上。
- 生成、复用和替换抽检批次：`operator` 及以上。
- 用户管理、角色分配、权限变更：仅 `admin`。
- 历史批次不直接删除；替换仍通过废弃旧批次并保留审计记录完成。

## 审计与迁移

- 记录登录、登出、查看、生成、替换、用户停用和权限变更。
- 首个管理员账号通过 `npm run auth:bootstrap` 在本地交互式创建，不允许通过公开注册创建管理员。
- 后续使用者由管理员创建账号并告知登录信息；首个管理员仍通过受控初始化脚本创建。
- 管理员页面支持创建用户、调整角色、停用/恢复账号、重置密码和查看最近审计记录。
