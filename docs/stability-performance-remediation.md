# 稳定性与性能整改口径

## 目的

修复名单解析、阶段性报告判定、匹配索引和 Excel 输出的已确认风险，同时保持现有业务结果、输入表和输出表合同。本文档先于代码修改建立，后续实现与验收均以此为准。

## 现行合同与不可变规则

- 打卡仍按教师邮箱优先匹配聊天；教师免检不作为有效证据。
- 阶段性报告有教师邮箱时精确匹配；无邮箱时才按去空格、去末尾数字和“老师”后的教师姓名兜底。
- 学员证据仍优先使用清洗后姓名后两字；不足两字使用末字；群名和聊天内容均可命中。
- 阶段性报告只回填原表的发送状态列；原申诉字段、字段顺序和五个输出 Sheet 不改变。
- 阶段性报告出现教师或学员缺失、姓名兜底对应多个邮箱时，视为未决数据：阻止生成可上传文件，报出源行号和原因，不写“否”。
- 打卡有教师邮箱时按“教师邮箱 + 学员号”去重；学员号为空才退回清洗后学员姓名。教师邮箱为空的源行不自动合并，保持逐行可追溯并计入告警。
- 白名单单字关键词仍遵循现有匹配口径，但输出必须说明关键词来源；不把白名单证据改成显示姓名。

## 低优先清理

- `weekOfMonth` 统一为单一实现。
- 项目组、实验P/实验C、助理主管本人教研组归属使用同一套映射。
- ZIP 告警只吞掉单参数、完全匹配的已知可恢复告警；其他告警保留。
- 教师后缀使用字面量“老师”，不再通过 URL 解码构造。

## 输出接口调整

- 阶段性报告匹配结果增加未决行明细，导出前必须为空。
- 打卡最终表和匹配明细增加“命中关键词来源”。
- Worker 完成消息从单个 `buffer` 改为 `chunks` 与 `byteLength`；下载函数直接接收 Blob 分块。
- 回归脚本可在测试边界合并分块；生产 Worker 不合并。

## 验收顺序

1. 运行 typecheck 与全部逻辑测试。
2. 运行 build，验证分块协议、ZIP 完整性和输出可重开。
3. 使用真实名单与累计聊天文件回归，逐项核对 Sheet、列、行数、时间和结论。
4. 运行 reminder、打卡、阶段性报告性能基准；确认无未决行时业务结果保持不变。
5. 检查 `git diff --check` 与工作树边界；不提交、不推送、不部署。

## 打卡真实基准（2026-08-22）

测试输入固定为同一份课堂反馈名单和 `总聊天质检明细_打卡_20260713~20260720.xlsx`：

- 基线版本两次端到端平均：9.97 秒。
- 当前版本两次端到端平均：8.73 秒，约快 12.4%。
- 当前匹配明细保留 1,350 条最佳证据；基线若保留全部命中约 10,848 条，减少约 87.6%。
- 输出从 11,520,712 字节降至 8,971,905 字节，减少约 22.1%。
- 打卡专用 SheetJS 读取关闭 `cellText` 生成；打卡 ZIP 使用压缩级别 3。阶段性报告和 reminder 保持压缩级别 6。
